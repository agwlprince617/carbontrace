          What would make this estimate defensible? ⌄
                  
          For now, the displayed numbers use assumptions. This applies to the optional hardware illustration only; the CLEER reference above uses published workload energy. Neither establishes your prompt’s actual emissions or proves a carbon saving. API price is not an energy measurement. Illustration ranges describe different assumptions, not confidence intervals.
          
                  
          
                  
          To calculate a supported estimate: obtain energy telemetry or a validated energy model for the exact model, version, and deployment; account for batching, shared hardware, idle power, CPU, and memory; and match the request to a serving region, time, facility PUE, and a documented electricity-emissions factor. Multiply attributed electricity in kWh by that factor in gCO₂e/kWh. If the energy data already includes facility overhead, do not apply PUE again.
          
                  
          Validate the prediction against representative request lengths and workloads, publish its error and source dates, and count all attempts and retries. Training, hardware manufacture, networking, and user devices need separate lifecycle accounting; this demo covers operational electricity only.
          
                  
          Google’s published measurement approach ↗ is useful methodology context. Its Gemini Apps aggregate does not calibrate these two API model scenarios.
